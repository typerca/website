A better score doesn't mean a safer agent.

  • Right answer, wrong reasons.

    A higher accuracy number doesn't tell you whether the agent ignored evidence against its answer, or stopped before checking the alternatives.

  • Self-checks aren't proof.

    The team that builds an agent shouldn't be the only one deciding whether it worked. Neither should the agent.

  • Human approval doesn't scale.

    If an engineer has to re-check every recommendation by hand, the agent hasn't earned autonomy. It has moved the work.

Game day: how it works.

Scored on how the agent got there, not just where it ended up.

  1. We break a realistic system on purpose. A known failure, so the true cause is known exactly.
  2. Your agent investigates. It queries recorded telemetry as if the outage were live.
  3. We record every step. What it looked at, what it concluded, what it recommended.
  4. TypeRCA scores the investigation. Against the known cause, with rules written before the run.
  5. Change the agent, run it again. See exactly which incidents got better or worse.

How scoring works.

Every investigation is broken into narrow questions with fixed answers. Does this evidence support the claim? Was the network ruled out? Does this observation contradict the deploy? A decision model answers each one (today, TypeSafe's Jev). Plain code applies the rules, and every verdict shows exactly which rule it passed or failed.

Plain code decides.
